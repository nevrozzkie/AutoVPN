# Zapret2: первый этап, VPN transport (0.9)

Реализован опциональный локальный nfqws2 на внешних соединениях AutoVPN с VPN-серверами.
Это **не дополнительное шифрование**, не настройка VPN-exit и не гарантия обхода DPI.
Стратегии зависят от провайдера; packet-level проверка на WR3000S ещё не выполнена.

## Настройка в LuCI

1. **Services → AutoVPN → Settings → Zapret2 engine → Install / check installation**.
   Установка идёт в фоне и не меняет VPN. Загружается зафиксированный официальный
   релиз bol-van/zapret2, проверяется SHA-256; upstream-установщик не запускается.
   Подробности и точные хеши: [установщик движка](zapret-install.md).
2. Включить **Zapret on VPN transport**, выбрать стратегии по протоколам.
3. Сохранить настройки и нажать **Overview → Apply saved VPN settings**.
   Если проверка новой конфигурации не проходит, восстанавливается предыдущая,
   включая её zapret-настройки. Сохранённые поля LuCI могут при этом отличаться от
   реально восстановленной конфигурации: для следующей попытки их нужно исправить.
4. Использовать **Ping all** для проверки YouTube/Instagram через каждый кандидат.

Установка движка и включение обработки — отдельные явные действия. Нет автоматических
обновлений движка, подбора стратегий, отключения zapret при ошибке или переключения
исправного VPN ради меньшей задержки. `Auto` сохраняет ранее заданное поведение.

## Что обрабатывается

Одна существующая VPN-сеть (`br-avpn`) с тем же выбранным VPN. Настройка действует
также на кандидатные проверки, чтобы резервный VPN проверялся в тех же условиях.
В отдельную NFQUEUE 20195 идут только первые 12 исходящих пакетов соединения,
совпавшие одновременно с WAN-интерфейсом, точным IPv4/портом и внутренней меткой
AutoVPN. У TCP также передаются FIN/RST для завершения состояния.

| Протокол | Внешняя метка | Начальная стратегия |
| --- | --- | --- |
| VLESS REALITY | 20201 | Разделение TLS ClientHello |
| Hysteria2 | 20202 | UDP fake с некорректной контрольной суммой |
| AmneziaWG | 20194 (существующая внешняя метка AWG) | Выключено; UDP fake включается явно |

У AWG внутренняя метка 20193 не меняется. У прямых исключений, API подписки, обычного
DNS и остальных приложений нет этих меток: их трафик не поступает в NFQUEUE.
Для UDP fake-пакетов можно задать 1–6 повторов. Это пробная стратегия, не универсальный
обход AWG/HY2; исходные UDP-пакеты не меняются. Она учитывает неизвестный для DPI
формат payload (например, обфускацию HY2 или изменённые заголовки AWG).
Выбор `Off` для конкретного протокола оставляет его доступным без обработки zapret.

## Запуск, остановка и восстановление

Контроллер сначала закрывает клиентский forwarding и останавливает VPN, затем
устанавливает узкие nft-правила и запускает nfqws2; только после готовности очереди
запускаются AWG/sing-box. Forwarding открывается после обычной проверки VPN.
Настройки zapret входят в тот же runtime bundle и откатываются вместе с ним.
Независимого автозапуска сервиса нет. Периодическая проверка контролирует процесс,
очередь и неизменность правил, восстанавливая тот же VPN при отказе обработчика.

Правила находятся только в `inet autovpn_zapret` с marker chain. Чужая таблица с тем
же именем не удаляется. Повторно сгенерированные пакеты имеют дополнительный бит
0x40000000 и исключены из перехвата; notrack ограничен тем же endpoint и WAN.
`queue bypass` не используется: новые обработанные handshake не могут молча пропустить
умерший обработчик. Уже установленные соединения после первых 12 пакетов всё ещё
передают зашифрованный VPN-трафик; это не обещание мгновенной остановки каждого пакета
при падении nfqws2. Сети никогда не переводятся на прямой WAN из-за отказа VPN.

Нужен `kmod-nft-queue` из официального OpenWrt feed, добавленный в зависимости APK.
Flow offloading по-прежнему запрещён проверкой AutoVPN. Включается глобальный
`net.netfilter.nf_conntrack_acct=1` для ограниченного перехвата начальных пакетов;
при остановке он не выключается, чтобы не нарушить работу других правил.
Временные конфиги и состояние живут в RAM; периодический health не пишет их во flash.
Сброс AutoVPN выключает zapret и убирает его runtime-данные, но оставляет установленный
движок. Wi-Fi/LAN и прошивка не изменяются.

## Что ещё не реализовано

Отдельные `-ZAPRET` и `-VPN-ZAPRET` SSID остаются выключенными. Один общий внешний
VPN-сокет нельзя одновременно обрабатывать по-разному в зависимости от исходного SSID;
для этого нужен следующий этап с разделением транспортов и маршрутов.
Не реализованы произвольные Lua/командные строки, autohostlist и blockcheck из панели.
Финальный APK/образ с движком ещё не измерен, реальный обход блокировок не проверен.

## Upstream

Используется [zapret2 v1.0.5](https://github.com/bol-van/zapret2/releases/tag/v1.0.5).
Аргументы, POSTNAT-перехват, rawsend marks и режим проверки сверены с
[официальным manual этой версии](https://github.com/bol-van/zapret2/blob/v1.0.5/docs/manual.md).
Классический zapret находится в EOL; новый backend основан на nfqws2.
