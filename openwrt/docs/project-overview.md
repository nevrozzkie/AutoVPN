# Обзор роутерного компонента AutoVPN 2.0

Документ перенесён вместе с исходниками в `AutoVPN/openwrt/`.

Проект OpenWrt-приложения для Cudy WR3000S v1 на OpenWrt 25.12. Уже реализованы
нативный ucode control plane, HTTPS adapter, transactional journal, recovery,
fail-closed и LuCI-страницы статуса/настроек/сетей. Runtime запускает VLESS и
Hysteria2 через sing-box и опциональный kernel AmneziaWG. Добавлено автосоздание
WPA2 SSID с пользовательскими базовым именем и паролем, подтверждением и откатом.
В 0.9 добавлен [zapret2 для внешних VPN-соединений](zapret.md); отдельные zapret-SSID
пока выключены. Проверка сети на самом роутере не выполнена.

В 0.6 добавлены установщик для одной команды из GitHub Release и первичная
настройка в LuCI: URL сайта, Router ID/токен, имя Wi-Fi, WPA2-пароль, определение
WAN, создание/подтверждение сетей и включение службы. Сайт не раздаёт установочные
файлы. [Инструкция и статус релиза](../README.md): код подготовлен
локально, APK ещё надо собрать, измерить и проверить на OpenWrt; ничего не опубликовано.

## Цель

Один LuCI-интерфейс должен:

- получать версионированную конфигурацию с пользовательского HTTPS-сайта;
- управлять VLESS и Hysteria2 через `sing-box-tiny`;
- управлять kernel AmneziaWG отдельным интерфейсом; в 0.5 поддержан профиль v1
  текущего сервера, lifecycle принадлежит контроллеру (не netifd);
- автоматически создавать изолированные сети `direct`, `vpn`, `vpn_zapret`
  и `direct_zapret`, не затрагивая административную `lan`;
- отправлять российские ресурсы напрямую, а остальной трафик сети `vpn` — через
  выбранный туннель;
- при необходимости применять локальный `nfqws` к внешнему соединению роутера с
  VPN-сервером, до провайдера;
- обновлять всю рабочую конфигурацию одной ревизией с проверкой, откатом и
  сохранением предыдущей версии;
- поддерживать сброс приложения и отдельный полный factory reset устройства.

## Важная граница VPN + zapret

Zapret здесь — не сервис на VPN-exit и не обработка пользовательского трафика после
туннеля. `nfqws` работает на роутере с **внешним transport flow до VPN-сервера**,
пока пакет ещё проходит через WAN и DPI провайдера: TCP для VLESS и UDP для
Hysteria2/AmneziaWG. После этого VPN продолжает штатно шифровать и передавать весь
пользовательский трафик.

В NFQUEUE попадают только пакеты, одновременно совпавшие с текущим endpoint IP,
port и WAN egress выбранного VPN-профиля. Обычный пользовательский трафик,
подписка/API, DNS и трафик до других хостов туда не направляются. Стратегии строго
protocol-specific: совместимость VLESS/TLS не означает совместимость с QUIC/UDP
Hysteria2 или AWG. Поэтому режим `vpn_zapret` означает «тот же VPN, но его внешний
transport обрабатывается локальным nfqws», без отдельного серверного VPN-профиля.

Режим `direct_zapret` остаётся опциональной отдельной сетью для прямого трафика,
если после packet-level PoC окажется полезен для конкретного провайдера.

## Несколько физических роутеров

Сайт ведёт реестр роутеров. У каждого устройства есть неизменный `router_id`, своё
локальное состояние и отдельный сменяемый Bearer token. Token аутентифицирует
конкретный `router_id`, но не является его постоянной идентичностью: его можно
отозвать или заменить без потери истории, назначенной политики и последней рабочей
ревизии. Один VPN-клиент назначается одному роутеру, особенно для AmneziaWG, чтобы
не было конкурирующих handshake с одинаковыми ключами.

Snapshot и ETag формируются для конкретного роутера: общая серверная ревизия может
быть одной, но policy, протокол, zapret и ключи — разными. Роутер локально сверяет
`router_id` из snapshot с UCI-настройкой и отвергает несовпадение. Статусы применения
и `last_seen` сохраняются сервером в разрезе `router_id`; недоступность одного
устройства не влияет на остальные.

## Принятые ограничения этапа 1

- целевая платформа: только `cudy_wr3000s-v1`, `mediatek/filogic`,
  `aarch64_cortex-a53`, OpenWrt 25.12.x;
- только stock-layout; переход на U-Boot-mod не является частью проекта;
- managed-сети на первом этапе работают только с IPv4, чтобы не допустить обход
  политики через IPv6;
- никаких Python, Node.js и контейнеров на роутере; control plane — `ash`/`ucode`,
  UCI, ubus/rpcd и procd;
- подписка передаёт типизированные поля, но не shell-команды, произвольный JSON
  sing-box или исполняемые файлы;
- при недоступном VPN сети `vpn` и `vpn_zapret` закрываются, а не падают обратно
  на WAN;
- токен и приватные ключи никогда не отображаются повторно в LuCI и не попадают в
  обычные логи.

## Бюджет устройства

Cudy WR3000S v1 имеет 256 МиБ RAM и 128 МиБ NAND, но штатный UBI-раздел под систему
ограничивает практический бюджет образа примерно 40 МиБ. Предыдущая контрольная
сборка OpenWrt 25.12.5 с `sing-box-tiny` и `kmod-nft-queue` дала SquashFS около
12.84 МиБ. Это подтверждает направление, но **не** гарантирует финальный состав:
перед реализацией необходимо собрать одним ImageBuilder/ASU-запросом образ со всеми
выбранными зависимостями, AWG, минимальным zapret и LuCI-приложением.

Постоянно хранятся только текущая и предыдущая ревизии. API ограничивает размер
manifest и artifacts, а большие временные файлы загружаются последовательно.
