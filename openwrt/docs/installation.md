# Установка AutoVPN на Cudy WR3000S v1

Корневой `install.sh` репозитория устанавливает **сайт на сервер**, не роутер.
Здесь описан отдельный OpenWrt-установщик и последующая настройка в LuCI.

## Что уже готово и что ещё нельзя считать проверенным

Controller 0.14.5, AmneziaWG tools и модуль собраны и подписаны для OpenWrt
25.12.5, `mediatek/filogic`, `aarch64_cortex-a53`. Требуемый пакет kernel:
`6.12.94~5a6c1f71be683ae9980b15d3ce73e24d-r1`.
Сборка не равнозначна проверке установки, загрузки модуля или VPN handshake
на роутере. [Артефакты и измеренный размер](awg-sdk-build.md).

Доступен [предварительный установочный релиз 0.14.5](https://github.com/nevrozzkie/AutoVPN/releases/tag/router-v0.14.5-openwrt-25.12.5-r1).
Он сохраняет исправления предыдущих выпусков и исправляет native ucode-вызов
maintenance, из-за которого Rebind завершался `maintenance_failed`. Resume
после обновления теперь также умеет безопасно оставить ещё не привязанный
контроллер выключенным и вернуть его в мастер настройки. Также исправлен запуск
HTTP-адаптера: числовые таймауты теперь передаются процессу строковыми аргументами,
а первый `Refresh snapshot` больше не завершается `adapter_start_failed`.
AmneziaWG APK не изменены.
Установщик по-прежнему устанавливает `coreutils-stty` для скрытого ввода пароля.
Команда ниже загружает готовый установщик из него. Нельзя просто
запустить исходный `openwrt/scripts/install.sh`: это шаблон, который откажется
работать без закреплённых manifest, хеша и публичного ключа. Не подставляйте
вместо него корневой серверный установщик. Подготовка новых выпусков описана в
[инструкции выпуска](releases.md); эти шаги не нужны обычному пользователю.

## 1. Подготовка

- Cudy WR3000S **v1**, штатная разметка flash, уже установленный OpenWrt.
  Перепрошивка и изменение U-Boot не требуются и не выполняются скриптом.
- Работающий интернет на WAN. **PPPoE необязателен**: существующий DHCP,
  статический адрес или PPPoE не надо заменять. Для нестандартных firewall/WAN
  конфигураций сначала нужна проверка совместимости установщиком.
- Доступ к SSH и LuCI по кабелю LAN. Не делайте первую установку через
  единственное Wi-Fi-подключение: беспроводные сети будут перенастраиваться.
- Резервная копия OpenWrt: **System → Backup / Flash Firmware → Generate archive**.
  Храните архив приватно: в нём могут находиться пароли и ключи.
- Обновлённый сайт AutoVPN 2.0 с HTTPS и включённым Router API.
  [Установка и обновление сайта](../../docs/server-installation.md).

Для сверки модели, версии и свободного места можно выполнить по SSH:

```sh
ubus call system board
uname -r
apk query --installed --match name --fields name,version --format json kernel
df -h /overlay /tmp
```

Проверять нужно полный kernel ABI, не только `uname -r`. Не используйте
принудительную установку неподходящего модуля или отключение проверки подписей.
Реальный запас места проверяет installer по release manifest; измерение
логического размера файлов не гарантирует столько же свободного места после
записи на flash.

## 2. Установка одной командой

Выполните по SSH от root, подключившись к роутеру кабелем LAN. Команда подходит
для указанного выше OpenWrt 25.12.5 и точного kernel ABI; ничего подставлять не нужно:

```sh
(autovpn_bootstrap="$(mktemp /tmp/autovpn-bootstrap.XXXXXX)" &&
  trap 'rm -f "$autovpn_bootstrap"' EXIT &&
  wget -O "$autovpn_bootstrap" 'https://github.com/nevrozzkie/AutoVPN/releases/download/router-v0.14.5-openwrt-25.12.5-r1/install.sh' &&
  sh "$autovpn_bootstrap")
```

Если сначала нужен preflight, скачайте этот же файл и запустите с `--check`.
Проверка скачивает данные и пишет временные файлы, но не устанавливает пакеты
и не применяет UCI-настройки. Не следует называть её полностью read-only.
Она проверяет APK-план, но не запускает отдельный установщик zapret: ошибка его
скачивания возможна уже после установки APK, до изменения Wi-Fi. В таком случае
сохраните вывод ошибки; не отключайте проверку подписей и не переустанавливайте прошивку.

Для чистой установки требуется минимум **38 МиБ свободного `/overlay` и 64 МиБ `/tmp`**.
Порог рассчитан по размерам файлов и зависимостей с запасом, а не по результату
установки на устройство. [Проверки релиза и бюджет](installer-release-r2.md).
Дополнительный `coreutils-stty` занимает 73 925 байт файлов и 34 538 байт APK
по каталогу 25.12.5; он укладывается в запас r2, пороги manifest не уменьшены.

Обычные зависимости берутся из официальных OpenWrt feeds; custom APK и
закреплённый installer — из GitHub Release; zapret — из закреплённых upstream
источников. Сайт AutoVPN отдаёт подписку и ключи, не установочные файлы.

При первой установке скрипт запросит:

- базовое имя Wi-Fi `x`: от 1 до 27 **байт UTF-8**, чтобы хватило места суффиксам;
- WPA2-пароль с повтором и скрытым вводом: 8–63 печатных ASCII-символа либо
  64 шестнадцатеричных символа. Не передавайте пароль в командной строке.

На обоих диапазонах создаются четыре сети с одним WPA2-паролем:

| SSID | Назначение |
| --- | --- |
| `x` | Обычный интернет и администрирование в существующей LAN |
| `x-в` | VPN |
| `x-з` | Прямое подключение с zapret, без VPN |
| `x-вз` | VPN с обработкой внешнего трафика туннеля через zapret |

Имена на 2,4 и 5 ГГц одинаковые. **Диапазон выбирает клиент**; активный
band steering не устанавливается. Это не гарантия автоматического перехода
каждого телефона на лучший диапазон.

После создания сетей есть **3 минуты на подтверждение**. Сохраняйте кабельный
SSH, проверьте подключение к `x` другим устройством и подтвердите результат
в терминале. Без подтверждения применяется откат сетевых изменений. VPN-сети
до готовности соответствующего подключения закрыты и не подменяются обычным WAN.

### Если 0.14.0–0.14.4 установил пакеты, но привязка к сайту не завершена

Не запускайте полную установку заново и не удаляйте trust/journal-файлы.
Для ошибок `No module named 'autovpn.network-transaction'` и
`timeout: applet not found`, а также `setup_failed` при ещё не сохранённой
привязке предусмотрен отдельный ремонт **ещё не привязанного** контроллера:

```sh
(autovpn_repair="$(mktemp /tmp/autovpn-repair-bootstrap.XXXXXX)" &&
  trap 'rm -f "$autovpn_repair"' EXIT &&
  wget -O "$autovpn_repair" 'https://github.com/nevrozzkie/AutoVPN/releases/download/router-v0.14.5-openwrt-25.12.5-r1/repair-bootstrap.sh' &&
  sh "$autovpn_repair")
```

Скрипт проверяет существующий ключ доверия, закреплённые SHA-256 и подпись APK,
заменяет только controller. Если первичный Wi-Fi уже создан и его транзакция
подтверждена, скрипт проверяет неизменность настроек и не запускает мастер Wi-Fi
повторно: после обновления продолжайте First setup в LuCI. Если Wi-Fi ещё не
создан и сетевого журнала нет, запускается установленный мастер Wi-Fi.
Ядро, AmneziaWG, WAN и настройки сайта не переустанавливаются. Существующие
настройки сохраняются; мастер Wi-Fi отдельно запросит имя, WPA2-пароль и
подтверждение сетевых изменений. Для уже привязанного к сайту роутера или
незавершённой сетевой транзакции этот узкий repair откажется работать:
сохраните ошибку, не сбрасывайте конфигурацию вручную.

Если старый выпуск оставил зависший процесс `lock`, исправление не убивает его
автоматически: это могло бы прервать живую операцию. Не удаляйте lock-файл и не
убивайте PID вслепую; сначала убедитесь, что нет выполняющегося обновления или
сетевой транзакции. Само наличие файла `.lock` после обновления нормально —
занятость определяется ядром, а не наличием файла.

## 3. Привязка сайта в LuCI

1. На сайте создайте отдельного клиента для физического роутера в `/admin/clients`.
   В `/admin/routers` выберите его и нажмите **«Добавить и выпустить токен»**.
   Сохраните Router ID и показанный credential приватно. Для каждого роутера
   нужна отдельная запись; не копируйте один Router ID и токен на несколько устройств.
2. В OpenWrt откройте **Services → AutoVPN → Setup**. Введите HTTPS-адрес
   сайта, Router ID и credential. Имя Wi-Fi уже заполнено; пустое поле пароля
   сохраняет установленный пароль.
3. Нажмите **Save pairing and Wi-Fi settings**. Если сети уже созданы и
   подтверждены установщиком, повторно создавать их не нужно. На старой
   установке без bootstrap используйте **Create managed Wi-Fi**, проверьте
   доступ и нажмите **Keep these networks** в пределах окна подтверждения.
4. Нажмите **Enable AutoVPN**. В **Overview** проверьте результат
   **Refresh snapshot** и **Apply saved VPN settings**.

Контроллер использует `GET /api/v2/router/snapshot/dual`: старого API недостаточно.
`404` означает, в частности, старую версию сайта или отключённый Router API,
а не повод выключать HTTPS. Дополнительный AWG peer для второй сети выдаётся
через Router API, а не добавляется в обычную пользовательскую подписку.

## 4. Выбор VPN, маршрутизация и zapret

В **Settings** у `x-в` и `x-вз` отдельные режимы выбора: VLESS, Hysteria2,
AmneziaWG или **Automatic (failover only)**. Auto меняет подключение только
при отказе текущего; более быстрый ответ другого VPN сам по себе не повод
переключаться. В **Overview** запускайте **Ping all** отдельно для каждой сети:
это HTTPS-проверки через соответствующие подключения, не ICMP ping сервера.

**Automatic Russian bypass** по умолчанию включает общие для обеих VPN-сетей
доменные/IP-исключения. Это регулярно обновляемая community-база, а не гарантия
охвата каждого российского сайта. Дополнения задаются в **Domains without VPN**
и **IPv4 networks without VPN**. После сохранения настроек используйте
**Apply saved VPN settings**. [Подробности и ограничения](ru-routing.md).

**Zapret on VPN transport** относится к `x-вз`: обрабатывается внешний трафик
к VPN, а содержимое по-прежнему шифрует сам VPN. Zapret не является дополнительным
шифрованием и не гарантирует обход любой блокировки. У `x-з` свой переключатель
прямого zapret; его выключение закрывает эту сеть, а не превращает её в обычный WAN.
Настройки Discord discovery/STUN относятся к `x-з`; работоспособность голоса,
видео и демонстрации экрана нужно проверять у своего провайдера.
[Профили Discord](discord.md).

## 5. Обновление и восстановление

**Maintenance → Check release → Install checked version** запускается вручную:
автообновления приложения нет. После обновления требуется явное
**Resume AutoVPN**. Это обновление controller, не прошивки, kernel или AWG-пары.
Обновление подписки и базы российских исключений — отдельные механизмы.

Сброс AutoVPN в Maintenance не является factory reset роутера: WAN/LAN и Wi-Fi
сохраняются. После сброса или перепривязки VPN не открывается до явного
возобновления. Не публикуйте диагностические архивы без проверки на ключи и токены.
[Подробности восстановления](maintenance.md).

Перед повседневным использованием ещё необходима проверка на устройстве:
DHCP/DNS всех сетей, два AWG handshake одновременно, независимые Auto/Ping all,
отсутствие прямого WAN при отказе VPN, перезагрузка и реальные Discord-звонки.
Локальные тесты и успешная SDK-сборка эти проверки не заменяют.
