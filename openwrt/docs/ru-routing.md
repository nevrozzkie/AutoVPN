# Автоматическая база «российское без VPN» (0.12.0)

`Services → AutoVPN → Settings → Automatic Russian bypass` управляет общей
базой исключений для `x-в` и `x-вз`. На новых установках включена по умолчанию.
После изменения флага нужно сохранить настройки и нажать **Apply saved VPN
settings** на Overview. Сохранённые runtime старых версий не меняют поведение
сами: для подключения базы на существующей установке тоже нужно применить настройки.

База дополняет, а не заменяет `Domains without VPN` и `IPv4 networks without VPN`.
Отключение флага убирает только автоматическую базу; ручные `.ru`/`.рф` из
предыдущих настроек продолжают действовать. Выбор Auto и результаты Ping all
по-прежнему независимы у двух VPN-сетей.

## Содержание и пределы точности

Используются community-наборы SagerNet `geosite-category-ru` (российские
домены/сервисы, включая компании с доменами вне `.ru`) и `geoip-ru` (IP-префиксы,
классифицированные источником как RU). Источники и проверенные ограничения:
[ru-database-sources.md](ru-database-sources.md).

Это приближение, **не гарантия «всё российское»**. Список доменов может отставать,
а российский IP может обслуживать иностранные сайты на общем хостинге/CDN.
IPv6 и непубличные диапазоны из GeoIP не используются. Правила DNS-перехвата,
запрета IPv6/частных адресов и принудительные VPN-пробы имеют больший приоритет.
Неизвестный базе трафик остаётся в VPN.

Прямые исключения обходят и VPN, и его zapret-обработку. Обычная сеть `x` и
direct-zapret `x-з` от базы не зависят. DNS в VPN-сетях остаётся через VPN;
сторонний DoH/ECH ограничивает точность доменного сопоставления. При закрытом
VPN runtime прямые исключения тоже недоступны — обход kill-switch не добавлен.

## Обновление и отказоустойчивость

- Общий локальный source rule-set: `/etc/autovpn/routing/ru.json`.
  Пакет содержит минимальную офлайн-базу `.ru`, `.рф` и `.su`, поэтому старт VPN
  не ждёт GitHub. До первого успешного скачивания полной базы действует этот минимум.
- Отдельный procd instance запускает проверку при старте и каждый час;
  после успеха следующая загрузка разрешена через 24 часа, после ошибки — через час.
  Загрузка не блокирует health/Auto и не перезапускает туннели.
- Только фиксированные HTTPS URL upstream. При недоступности напрямую — попытки
  через локальный SOCKS активного VPN, затем VPN+zapret. Каждый запрос ограничен
  по времени и объёму; credentials сайта не передаются источникам базы.
- Обе базы должны успешно скачаться, декодироваться и пройти строгую проверку.
  Разрешены только домены, доменные суффиксы и IPv4 CIDR; произвольные правила,
  команды и внешние пути не принимаются. Итог дополнительно компилируется sing-box.
- Проверенный общий файл заменяется атомарно. На ошибке старая база сохраняется.
  sing-box перечитывает локальные правила без смены выбранного VPN. Уже открытые
  соединения не переводятся между маршрутами; новые используют обновлённые правила.
- Maintenance/update gates и выключенный флаг запрещают публикацию новой базы.
  Непривязанный роутер может скачать публичную базу: для неё аккаунт AutoVPN не нужен.

На Overview показываются время попытки/успеха и число доменных/IP-правил.
Это статус обновления файла, **не подтверждение применения каждой запущенной
lane**. Метаданные статуса хранятся в RAM: после перезагрузки сначала отображается
«ещё не проверено», но последняя база на флеш-памяти сохраняется. Reset/rebind
не удаляет публичную базу; reset возвращает флаг в включённое состояние.

Обновляется только база маршрутизации, не приложение, прошивка или zapret.
Управление маршрутизацией остаётся на роутере; сайт и прежние подписки не меняются.

## Проверка

`AUTOVPN_SING_BOX=/path/to/sing-box sh openwrt/scripts/check.sh` включает
проверки приоритетов, совместимости старых bundle, обновления при ошибках и
проверку конфигов реальным sing-box. Проверка OpenWrt nftables/маршрутизации
на самом устройстве остаётся отдельным этапом; роутер в этой задаче не изменялся.

На 2026-09-05 полный локальный gate прошёл: **296 passed, 0 failed, 0 skipped**.
Реальный sing-box 1.13.18 Darwin проверил конфиги и горячую замену одной базы
в двух SOCKS runtime без рестартов, включая сохранение прежних правил после
повреждённой замены. На актуальных данных источников merger получил
**1 092 доменных правила и 8 681 IPv4 CIDR**. Это host-проверка, не аппаратный
тест WR3000S и не подтверждение готовности установочного релиза.
