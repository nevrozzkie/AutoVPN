# SprintBOX: смена IP заменой бокса

Панель AutoVPN работает на отдельном сервере. В Setup выберите SprintBOX и задайте
API login, API key, имя текущего бокса (`box-…`), код тарифа и код образа ОС.
Если бокса ещё нет, оставьте его имя пустым: появится кнопка «Создать первый бокс».
Текущий IP для первого запуска не требуется. В разделе «Клиенты» должен быть хотя
бы один включённый клиент: его данные используются для проверки VPN до публикации IP.
Пустое поле API key при повторном сохранении сохраняет существующий ключ.
Секретный ключ не отображается в формах, списках боксов и журнале.

Для нового бокса AutoVPN автоматически создаёт и повторно использует отдельный
Ed25519 SSH-ключ. По умолчанию он хранится в `ssh/sprintbox_ed25519` рядом с БД
(для серверной установки: `/var/lib/autovpn/ssh/sprintbox_ed25519`). Каталог имеет
права `0700`, приватный ключ — `0600`. Приватная часть не отправляется провайдеру,
не хранится в SQLite и не выводится в журнал. В `box/add` передаётся публичный ключ.
Новый бокс устанавливается и проверяется как `root:22` с этим ключом, независимо
от сохранённого SSH-пароля прежнего VPS. Старые настройки сохраняются до успешной
проверки; вместе с публикацией IP панель переключает SSH на новый ключ и очищает
старый пароль. При ошибке прежний доступ остаётся неизменным.

На чистых серверах Xray устанавливается с `--version v26.7.28` для совместимости
с NekoBox 1.4.2. Уже установленный Xray этой командой не переустанавливается.
В конфигурации Reality явно задаётся `minClientVer: 1.0.0`: пустое значение в
Xray 26.7.28 означает минимум 26.3.27 и отклоняет версии, которые сообщают
sing-box/NekoBox. Проверка ключа, short ID и SNI сохраняется.

Если SSH нового бокса недоступен примерно минуту, на главной появляются три кнопки:
«Подождать ещё» повторяет ожидание того же бокса без создания нового;
«Создать другой бокс» создаёт следующий платный бокс, сохраняя прежние;
«Отмена» завершает попытку без смены текущего IP и без удаления серверов.
Неудачные боксы цепочки будут предложены к очистке после успешной установки и
нажатия «Всё ок». При отмене панель перечислит сохранённые боксы для ручного удаления.
Решение хранится в БД; перезапуск во время ожидания SSH возвращает к этому выбору.
Существующий ключ не перезаписывается. При ручном бэкапе сохраняйте каталог `ssh`
вместе с БД: это единственная приватная копия ключа. Для нестандартного размещения
можно задать `SPRINTBOX_SSH_KEY_PATH` в окружении сервиса.
ОС для AmneziaWG рекомендуется Ubuntu 24.04, с учётом требований существующего
установщика. Значение кода образа получите из API, не подставляйте название ОС наугад.

Настройки можно задать через окружение:

```dotenv
VPS_PROVIDER=sprintbox
SPRINTBOX_LOGIN=
SPRINTBOX_KEY=
SPRINTBOX_BOX_NAME=
SPRINTBOX_SERVICE=
SPRINTBOX_DISTRIBUTIVE=
```

Сохранённые в Setup значения имеют приоритет над окружением. Для совместимости
существующие установки без выбора провайдера продолжают использовать Aeza.

## Порядок операции

1. Зафиксировать VPN snapshot, провайдера, параметры тарифа/образа и fingerprint
   ключа API. Если имя текущего бокса задано, проверить, что он действительно
   владеет опубликованным IP. При создании первого бокса этот шаг пропускается.
2. Отправить `box/add` с названием вида `бокс-12345` (пять случайных цифр),
   проверенным на совпадения с существующими боксами, и публичным SSH-ключом.
   Длинный технический ID сохраняется только внутри операции AutoVPN.
3. Дождаться `status/show: finished`, найти ровно один новый бокс с этим описанием
   и единственным новым IPv4. Нельзя выбирать первый появившийся сервер на аккаунте.
   Дополнительные промежуточные статусы задачи считаются ожиданием; установка
   начинается только после `finished`. Неизвестный статус не подтверждает успех,
   ожидание ограничено таймаутом и не повторяет создание бокса.
   Если успешный ответ создания не содержит ID задачи, запрос не повторяется:
   панель ищет бокс по тому же описанию и продолжает только после появления нового
   IPv4. Если адрес не появился, ID найденного бокса сохраняется в журнале,
   прежний VPN остаётся активным. Проверьте статус и баланс в кабинете SprintBOX:
   неоплаченный бокс не запустится до пополнения. Перед новой попыткой требуется
   ручная сверка; перезапуск панели не создаёт второй бокс.
4. Дождаться SSH, установить VPN на чистый сервер и применить сохранённый snapshot:
   клиентские UUID, токены и криптографические ключи сохраняются.
5. Выполнить существующие проверки VLESS/Hysteria через новый endpoint.
6. В одной транзакции опубликовать IP и имя нового активного бокса, сбросить
   явно заданный старый SSH-хост, обновить ревизию подписок.
7. Показать на главной странице две кнопки и дождаться решения пользователя.
   Состояние ожидания сохраняется в БД, перезапуск панели его не сбрасывает.

**«Всё ок»** подтверждает, что пользователь проверил VPN. Только после этого
AutoVPN сохраняет отмеченные боксы как [якорные VPN](anchors-and-tuning.md),
а остальные старые боксы этой цепочки попыток ставит в очередь на ближайшее окно:
**23:30, 23:55, 04:00 или 07:00 МСК**. Очередь видна на главной странице админки; у каждой операции есть
кнопка **«Удалить сейчас»**. При очистке панель дожидается каждой фоновой задачи
и проверяет отсутствие бокса в `boxes/list`. Текущий активный
бокс, якорные боксы и посторонние боксы аккаунта не удаляются. Уже удалённые вручную пропускаются.

**«Попробовать другой IP»** создаёт следующий платный бокс и устанавливает VPN,
сохраняя все предыдущие. После установки снова появляются те же две кнопки.
Когда пользователь нажмёт «Всё ок», очистка охватит накопленные старые боксы.
Повторное нажатие старой кнопки и решение для уже сменившегося сервера отклоняются.

При включённом AmneziaWG до нажатия «Всё ок» проверьте handshake клиента через
новый IP. Автоматической полноценной AWG-проверки в проекте нет.
Импортированные статические профили Amnezia нужно обновить для нового адреса.

При явном отказе удаления (включая `41004`, если он реально возвращается) новый
VPN продолжает работать. В запланированной очереди явно отклонённые запросы
повторяются в следующее окно; без расписания требуется ручная проверка.
Очистка остальных боксов продолжается независимо от отказа одного из них.
Ошибки проверки бокса или уже принятой задачи требуют ручной проверки.
При потере ответа удаления результат считается неопределённым и включается hold.
Перезапуск панели не повторяет создание/удаление с неопределённым результатом.
Оба бокса могут оплачиваться до завершения очистки.

До публикации ошибка сохраняет старые IP и бокс; новый бокс может остаться платным.
Проверьте кабинет и журнал, выполните ручную сверку перед новой операцией.

## Смена IP пользователем и очередь удаления

На странице `/client/{token}` включённый пользователь может нажать «Сменить IP»
без входа в админку. Доступно для настроенного SprintBOX при включённых safe rotation
и transactional apply. После создания и проверки сервера страница обновляется
автоматически: пользователь обновляет подписку/ключ и выбирает «Да, всё ок» или
«Нет, сменить IP ещё раз». Подтвердить или повторить попытку может её инициатор;
администратор также может управлять ею в панели. Смена IP общая для всех клиентов.

После «Всё ок» старые серверы продолжают работать до ближайшего окна удаления:
23:30, 23:55, 04:00 или 07:00 по Москве. Расписание
хранится в SQLite; если окно пропущено из-за остановки приложения или занятого VPS,
очистка ждёт следующего окна. Администратор может запустить её сразу кнопкой
«Удалить сейчас». Несколько смен за день поддерживаются: проверяется текущий
основной сервер и защита якорей непосредственно перед удалением каждого бокса.
Явно отклонённый API запрос удаления повторяется в следующее окно с повторной
проверкой бокса и его IP; ошибка 41004 не трактуется как календарный запрет.
Неопределённые запросы удаления и ошибки уже принятой фоновой задачи автоматически
не повторяются даже в пересекающихся очередях.

При запуске записываются источник («Администратор» либо пользователь), ID и имя
пользователя на момент запуска. Они отображаются в очереди, последней смене IP
и журнале операций; последующее переименование не меняет историю. Для операций,
созданных до обновления, источник помечен как неизвестный.

## Первичный переход с Aeza

Для первого запуска выберите SprintBOX в Setup, заполните API login/key, тариф,
образ ОС. Поле текущего бокса оставьте пустым; SSH настраивается автоматически. На главной нажмите
«Создать первый бокс», проверьте параметры и подтвердите создание. Далее идут те
же установка, проверка, публикация IP и две кнопки выбора, что и при обычной смене IP.

Если старых боксов нет, очередь завершается без запросов удаления.
«Попробовать другой IP» создаёт следующий бокс и сохраняет первый; после проверки
нового кнопка «Всё ок» предложит очистить накопленные старые боксы.

При переходе с Aeza оставьте прежний IP до успешного завершения новой установки:
первый бокс SprintBOX публикуется только после проверки. VPS Aeza и посторонние
боксы аккаунта не добавляются в список удаления. Старый VPS Aeza удаляется отдельно
после проверки. Панель работает на отдельном сервере.

## Контракт и проверка

Используется опубликованный API: `https://api.from.sh/sprintbox/`, POST form data,
заголовки `AUTH-LOGIN` и `AUTH-KEY`. Создание, перезапуск и удаление возвращают ID
асинхронной задачи. Тарифы: `services/list`, образы: `distributives/list`.
Публичная документация не описывает отдельный параметр локации для `box/add`:
до использования подтвердите локацию выбранного тарифа/поведение API в аккаунте.
Интеграция не подставляет недокументированный параметр location.

Источники: [API](https://api.sprintbox.ru/),
[ключ API](https://cp.sprintbox.ru/customer/api/index).
Ответ `box/show` содержит VNC credentials, поэтому сырые ответы не выводятся в UI.

Локальные проверки используют mock API и тестовую БД. Живые создание, списание
денег, удаление, SSH-деплой и импорт клиентских профилей требуют отдельной проверки
с выбранным тарифом и учётными данными. При разработке эти действия не выполнялись.


### Ошибка изменившегося SSH-ключа нового бокса

Если во время настройки нового бокса появляется `Host key verification failed`,
под ошибкой доступна кнопка **«Пропустить ошибку SSH-ключа и продолжить»**.
Проверьте в SprintBOX, что IP принадлежит вашему новому или переустановленному
боксу, затем подтвердите действие. Панель удалит сохранённый ключ только для
IP этого бокса и повторит его настройку с проверкой нового ключа. Повторная
покупка не выполняется, старые боксы сохраняются до «Всё ок».
Кнопка доступна для последней операции при неизменных настройках и аккаунте;
другие ошибки установки или проверки VPN этим действием не пропускаются.


## Несколько аккаунтов SprintBOX

Откройте **«Аккаунты SprintBOX»** в меню панели (`/admin/sprintbox/accounts`).
Текущие учётные данные автоматически сохраняются как «Основной аккаунт»;
существующие боксы и якоря остаются привязаны к нему.

1. Добавьте новый аккаунт: название, логин и API-ключ.
2. Нажмите «Проверить доступ и тарифы». Список тарифов запрашивается через
   API именно этого аккаунта, включая доступные ему промотарифы.
3. Выберите тариф и образ ОС, сохраните настройки.
4. Нажмите «Использовать для новых боксов», затем запустите обычную смену IP.

Выбор аккаунта не покупает бокс и не меняет текущий VPN. Старый IP остаётся
основным до установки и проверки нового бокса. Управление текущим сервером,
очистка старых боксов и якорная защита используют владельца соответствующего
бокса, а не аккаунт, выбранный для следующей покупки. Даже одинаковые имена
боксов в разных аккаунтах учитываются отдельно. Якорные профили сохраняются.

Настройки аккаунтов и API-ключи хранятся в защищённой базе панели; ключи не
выводятся в HTML. Пустое поле нового ключа при редактировании сохраняет
текущий ключ. Логин добавленного аккаунта не меняется: для другого логина
добавьте отдельный аккаунт. Во время операции с VPS изменение и переключение
аккаунтов блокируется. Автоматического перехода между аккаунтами нет.

Ошибка API теперь показывает также поле `error.message`, если провайдер
не прислал `error.description`: например, `40101: Unknown service` означает,
что выбранный тариф не распознан. В этом случае проверьте список доступных
тарифов аккаунта и явно сохраните подходящий вариант.


## Новые боксы без автобекапов

При создании бокса AutoVPN всегда передаёт в `box/add` параметр
`scheduled=false`: автоматические бекапы SprintBOX не подключаются.
Это относится ко всем аккаунтам и всем новым боксам, включая первый бокс
и повторную смену IP. Для ранее созданных боксов расписание бекапов
меняется отдельно в кабинете SprintBOX; это обновление его не меняет.
Резервные копии базы самой панели при её обновлении сохраняются отдельно
и не являются услугой бекапов VPN-бокса.
