# Уведомления PWA

В личном кабинете: «Гайды» → «Уведомления». Разрешение запрашивается только по
кнопке «Включить уведомления». «Выключить уведомления» удаляет серверную подписку
этого устройства; другие устройства пользователя продолжают получать сообщения.
Загрузка страницы только читает существующее согласие и не подписывает повторно.
Отказ, закрытие запроса, отсутствие API, ошибки service worker и сети не мешают
использовать кабинет. Настройку можно повторить отдельным нажатием.

Нужен HTTPS. На iOS/iPadOS поддержка Web Push появилась в 16.4: нужно установить
PWA на экран «Домой» и открыть её оттуда. Браузер и ОС управляют показом, поэтому
приём push-сервисом не гарантирует доставку или прочтение.
Источник: [WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).

После успешной публикации нового основного IP подписавшимся активным пользователям
отправляется заголовок «Уведомление» и текст:
«Айпи был сменён. Не забудьте обновить конфиги».
Событие создаётся в транзакции публикации через отдельный savepoint: ошибка
постановки в очередь не отменяет изменение адреса. При неудачной смене и при
публикации прежнего адреса уведомление не создаётся. Ожидать подтверждения
пользователем или удаления старого сервера не нужно.

В админке → «Уведомления»: свой заголовок/текст, все подписавшиеся либо выбранные
пользователи, журнал состояний за 7 дней. Данные endpoints/ключей в интерфейс
администратора и логи не выводятся. Отключённые и удалённые пользователи
пропускаются, даже если сообщение уже было в очереди.

## Очередь и ключи

Миграция 14 добавляет `push_subscriptions`, `push_messages`, `push_deliveries`.
Ключ VAPID генерируется один раз в `settings.push.vapid`, вместе с базой попадает
в её защищённые резервные копии. Не удаляйте его при выкладке: смена ключа
потребует повторного включения уведомлений на устройствах.

Транспорт: `pywebpush` (зависимость в `pyproject.toml`), AES128GCM и VAPID.
`PUSH_VAPID_SUBJECT` при необходимости задаёт контакт оператора (`mailto:…`
или HTTPS origin без пути). По умолчанию используется публичный GitHub noreply
адрес автора репозитория. Закрытый ключ никогда не выдаётся браузеру.
Транспорт импортируется лениво, его отсутствие не ломает запуск приложения.

Отдельный фоновый worker, сетевой таймаут 8 секунд; до 6 попыток с экспоненциальной
задержкой, срок очереди — сутки, TTL отправленного сообщения — час.
404/410 удаляют истёкшую подписку; 400/401/403/413 прекращают попытки этой доставки;
429, сетевые и серверные ошибки повторяются. Незавершённая попытка после аварии
возвращается в очередь через 120 секунд. Идентификатор события и delivery уникальны;
повтор доставки после потерянного ответа возможен, но стабильный notification tag
заменяет прежнее уведомление без повторного звука, пока оно существует.

Push URL принимаются только для HTTPS endpoint известных сервисов Chrome,
Firefox, Apple и Edge. Произвольные адреса, нестандартные порты и HTTP отклоняются;
редиректы отключены. Перед отправкой ключи повторно валидируются.
Нажатие уведомления открывает только личную страницу этого же сайта.

Проверки: `pytest -q tests/test_web_push.py`,
`node --test tests/web_push_frontend.cjs`.
